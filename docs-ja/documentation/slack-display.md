# Slackの読み方

## レポートの確認場所 {#slack-display}

Slackでは、チャンネルの通知から変化や未解決状態を確認し、Botのスレッドから詳細を確認できます。
修正計画の表示は[Slackの修正計画](remediation-results.md#reading-results-in-slack-and-webhooks)を参照してください。

### チャンネルのレポート {#channel-display}

| レポート | 表示する内容 |
| --- | --- |
| `diff`モード | 前回からの変化と現在の未解決状態 |
| `full`モード | 今回のスキャンで確認した未解決の所見 |
| 週次レポート | 差分通知に加える、今回の未解決の所見の全体 |

変化のある差分通知には`前回のスキャンからの変化`、fullモードには`未解決の所見の全体`と表示します。
週次レポートの見出しは`📋 週次全体レポート — 未解決の所見の全体`です。

空の区分は表示しません。
トリアージ有効時の低優先度は完全レポートでも件数だけを表示し、全件の詳細は[汎用Webhook](webhook-reference.md#generic-webhook)で確認できます。

汎用Webhookを設定している場合は、`詳細は汎用Webhookのペイロードに記載`という案内を表示します。
通知の送信タイミングは[スキャン通知の送信条件](notification-conditions.md#notification-conditions)を参照してください。

### スレッドのレポート {#thread-display}

Botのスレッドは、`📊 未解決の所見の全体 — 日時`の見出しで、そのレポート時点の詳細を表示します。
チャンネル本文が複数のメッセージに分かれていても、スレッドは1通目に付きます。

| チャンネル本文1通目の末尾 | 確認先 |
| --- | --- |
| `📊 未解決の所見の全体はこのメッセージのスレッド ↓` | 今回投稿したスレッド |
| `🔗 前回のレポート時点の未解決の所見の全体 → スレッド` | 前回投稿したレポートのスレッド |

前回のレポートへのリンク先は、そのレポートを作成した時点の内容です。
今回の未解決状態は、チャンネルの[現在の未解決件数](#open-now)で確認してください。

長い通知は複数のメッセージに分かれ、続きの見出しには`(続き)`、チャンネルの続きには`(続き 2/3)`のような表示が付きます。
有効なリンクがない場合やリンクを表示できない場合は、末尾の案内を省略します。

新しいスレッドを投稿する条件は[Slackスレッドの投稿条件](notification-conditions.md#slack-thread-delivery)を参照してください。

## 通知の言語 {#notification-language}

Slackの定型文は、設定した通知言語で表示します。
言語の設定値と適用範囲は[設定](configuration.md)を参照してください。

| 対象 | 日本語通知での扱い |
| --- | --- |
| 見出し、区分、変化、警告、使用状況、案内 | 日本語で表示 |
| CVE ID、パッケージ名、版、パス、コマンド、イメージ名 | 元の表記を使用 |
| `CRITICAL`・`HIGH`などの深刻度 | 元の表記を使用 |
| Trivyの説明文、スキャン失敗のエラー文、議論リンクのラベル | 翻訳せずに表示 |

## 区分の並び順 {#section-order}

レポートの種類によって、変化を先に示す場合と、現在の未解決項目を区分別に示す場合があります。

### 差分レポートの並び順 {#diff-order}

変化がある回と週次レポートでは、次の順に表示します。
該当する内容がない区分は省略します。

| 順序 | 内容 |
| --- | --- |
| 先頭 | ヘッダー、イメージ件数、Sensorの警告 |
| 変化の前 | 脅威情報源を利用できない警告 |
| イメージの変化 | 実体変更、参照更新 |
| EOLの変化 | 新規EOLのベースOS、EOLパッケージの変化 |
| パッケージの変化 | 通常の新規検出・変化、解消・EOL解除 |
| 末尾 | 週次の現在状態レポート、またはスキャン失敗と現在の未解決状態 |

週次レポートではない変化なしの通知は、`前回のスキャンから変化なし`に続けて、スキャン失敗や現在の未解決状態を表示します。
実体未確認・保持の注釈は、未解決状態や完全レポートの後に付きます。

トリアージ有効時の通常の新規検出・変化は、優先度、イメージ名、パッケージ名の順です。

### 現在状態レポートの並び順 {#current-order}

トリアージ有効時は、次の順に未解決項目を表示します。
Botのスレッドも同じ区分順です。

| 順序 | 日本語の区分 | 英語の区分 |
| --- | --- | --- |
| 先頭 | ベースOSのサポート終了(EOL) | EOL base |
| 続き | パッケージのサポート終了(EOL) | EOL package |
| 優先度順 | 今すぐ対応 → 要監視 → 低優先度 | Act now → Watch → Low |

チャンネルのfullレポートでは、`優先度:`の行の直後、EOL区分より前に脅威情報源の警告を置きます。
週次レポートでは、警告は差分部分の先頭側に置き、完全レポート内には繰り返しません。

スキャン失敗や古い脅威情報の注記は、チャンネルの現在状態レポートの区分の後に表示します。

使用状況が有効な場合、同じ優先度では使用中のパッケージと、それを含むイメージを先に表示します。
使用中のパッケージ同士では公開状態や権限も並び順に使いますが、優先度そのものは変えません。

### トリアージ無効時の並び順 {#triage-disabled-display}

トリアージ無効時は、EOL区分に続いて、修正状態別に表示します。

| 順序 | 表示する区分 |
| --- | --- |
| 修正版あり | `✅ 今すぐ対応可能 (fixed)` |
| 修正版なし | `ℹ️ 修正版なし (affected / 上流の対応待ち)` |
| 修正予定なし | `🔕 このOSリリースでは修正予定なし (will_not_fix)` |

`今すぐ対応可能`は修正版がある区分で、トリアージの`今すぐ対応`とは意味が異なります。
修正状態の意味は[修正状態](scan-logic.md#status)を参照してください。

チャンネルでは、修正版ありのうち注意が必要な項目を個別に表示し、残りをイメージごとにまとめます。
使用状況による並べ替えは行いません。

## 件数の読み方 {#counts}

イメージ、パッケージ、CVEでは集計単位が異なります。
同じ通知内でも、件数が一致するとは限りません。

### イメージ件数 {#image-counts}

ヘッダーの`イメージN件をスキャン、M件に影響あり`は、次の単位で数えます。

| 表示 | 英語 | 集計単位 |
| --- | --- | --- |
| スキャンした件数 | images scanned | 失敗を含む、一意なイメージ参照と実体の組み合わせ |
| 影響ありの件数 | affected | 対象の脆弱性またはEOLのベースOSがあるイメージ参照 |

別の参照が同じスキャン結果を共有していても、スキャンした件数では別件として数えます。
スキャン失敗だけの参照は、影響ありの件数には含めません。

### 現在の未解決件数 {#open-now}

`📌 現在の未解決:`（Open now）は、今回のスキャン後に残る未解決状態を示します。
EOLと優先度の件数には、前回から保持している履歴も含めます。

| 表示 | 集計単位 |
| --- | --- |
| `⛔ EOLのベースOSN件` | EOLとして記録しているイメージ参照 |
| `⛔ EOLのパッケージN件` | ベースOSへまとめていない、イメージ参照とパッケージの組み合わせ |
| `🚨 今すぐ対応N件` | 通常側またはEOL側が今すぐ対応の、イメージ参照とパッケージの組み合わせ |
| `👀 要監視N件`・`🔕 低優先度N件` | 今すぐ対応に数えたものを除く、通常側の優先度別の組み合わせ |

EOL側の要監視・低優先度は、優先度の件数へ加算しません。
EOLパッケージと今すぐ対応の件数は重なる場合があります。

トリアージ無効時の`CRITICAL`・`HIGH`は、今回のレポートのパッケージグループごとのCVE件数を合計します。
同じCVEが別のグループにあれば、それぞれに数えます。

今回のレポートに検出項目がない場合は、件数の代わりに次の状態を表示します。

| 状態 | 表示 |
| --- | --- |
| Kubernetesの実体未確認でパッケージ履歴を保持 | `📌 現在の未解決: 未確認 — 再確認まで前回の所見を保持` |
| 上記以外で前回の履歴を保持 | `📌 現在の未解決: 未再スキャン — 次のスキャン成功まで前回の所見を保持` |
| 保持中の履歴もなし | `🎉 現在の未解決: なし — 問題なし` |

### Priority行の件数 {#priority-counts}

現在状態レポートの`優先度:`（Priority）は、今回のレポートのパッケージグループ数を示します。
修正状態が異なるグループや、同じ参照の別実体にあるグループは別件です。

| 件数 | 対象 |
| --- | --- |
| EOLのベースOS | EOLのイメージ参照 |
| EOLのパッケージ | ベースOSへまとめていないEOLグループ |
| 今すぐ対応 | EOLを含む今すぐ対応のグループ |
| 要監視・低優先度 | 通常のパッケージの各優先度のグループ |

同じ参照とパッケージをまとめる[現在の未解決件数](#open-now)とは、数え方が異なります。
通知オフによる除外は[通知オフの表示](#muted-display)を参照してください。

### 未解決の経過日数 {#unresolved-age}

未解決の最長期間は、対象となる履歴の最も古い初回検出日時から数えます。
1日以上で日数を表示し、14日以上では`⏰`を付けます。

| トリアージ | 最長期間の対象 |
| --- | --- |
| 有効 | 通常の今すぐ対応・要監視、EOLのベースOS、個別表示するEOLパッケージ |
| 無効 | 通常の全パッケージとEOL |

ベースOSへまとめたEOLパッケージは、ベースOSの初回EOL検出日で数えます。
ただし、今すぐ対応のEOLパッケージは、まとめられていてもパッケージ自身の初回EOL検出日を対象に含めます。

保持中の履歴も対象です。
トリアージ有効時は、今回通知オフと判定した通常のパッケージを最長期間から除きます。

| 表示例 | 意味 |
| --- | --- |
| `⏰ 今すぐ対応/要監視の未解決の最長期間20日` | トリアージ有効時の最長期間で、EOLも対象 |
| `⏰ 未解決の最長期間20日` | トリアージ無効時の最長期間 |
| `⏱ 未解決20日 · 初回検出2026-06-04` | スレッドのカードに表示する、そのパッケージの期間 |
| `⏱ 本日初検出` | スレッドのカードで経過日数が0日の表示 |

汎用Webhookの期間は集計対象が異なります。
比較する場合は[未解決の最長期間](webhook-reference.md#oldest-open-days)を参照してください。

## パッケージカードの読み方 {#package-card}

パッケージは`◆ 名前`のカードで表示します。
チャンネルの今すぐ対応は詳細カード、要監視などは簡略カードを使います。

| 項目 | 詳細カード | 簡略カード |
| --- | --- | --- |
| 現在の版・修正版 | それぞれ別の行 | 同じ行 |
| 更新の注意度 | `更新の注意度:`の行 | 修正版の後の括弧内 |
| 検出件数 | `CRITICAL`・`HIGH`の件数 | 同左 |
| 対応 | 条件を満たす場合に、`検出件数:`の次の行で元イメージの更新待ちを表示 | 同左 |
| CVE | 代表CVEと悪用情報、参照 | 表示できる場合に代表CVE |
| 使用状況 | 使用中の観測根拠 | 使用中の場合に短い表示 |

`検出件数:`は、そのパッケージと修正状態のグループ内で重複を除いたCVE IDの件数です。
修正版がない場合は`修正版: なし`と表示し、詳細カードでは緩和策や置き換えの案内が付く場合があります。

### CVEの表示 {#cve-details}

`代表CVE:`（Top CVE）は、そのグループで最も強い判定のCVEです。
優先度、EPSSの取得有無、EPSSの高さ、CVE IDの順で選びます。

| 表示場所 | ほかのCVEの扱い |
| --- | --- |
| チャンネルの詳細カード | `代表CVE:`の行に`(このパッケージにほか +N件のCVE)`を付加 |
| スレッド | `ほかのCVE:`にIDを並べ、省略分を`(ほか +N件)`で表示 |
| 差分カード | 追加されたIDを`変化: 新しいCVE ...`で表示 |

詳細カードの`EPSS n/a`は、スコアがないことを示します。
非常に小さい値は`<0.1%`、非常に大きい値は`>99%`と表示します。

スレッドの`説明:`には、Trivyの説明文を表示します。
省略されていないCVEの全データは[脆弱性のフィールド](webhook-reference.md#vulnerability-fields)で確認できます。

### 元イメージの更新待ちの表示 {#base-image-wait}

```text
対応: 元イメージ elasticsearch 8.19.23 の新しい版待ち（同じ系列に新しい版なし）
```

表示の意味は次のとおりです。

- その所見のパッケージは、Dockerfileの`FROM`で指定する元イメージに含まれる
- たとえば、Elasticsearchの公式イメージ`8.19.23`に同梱される`org.jsoup:jsoup`などのjarが対象になる
- 修正計画は、元イメージの同じ系列に新しい版（タグ）がないと判定している
- パッケージの修正版があっても、プロジェクト側でその所見を直すPRはまだ作れない
- 同じ系列に元イメージの新しい版が出ると、元イメージを上げるPRの候補になる
- 名前は元イメージのリポジトリ名の最後の部分でレジストリのホスト名を含まず、版はDockerfileの`FROM`が指定するタグを示す

次の条件をすべて満たす場合に、詳細カード・簡略カード・スレッド・差分カードの`検出件数:`の次の行に表示します。

- 同じ回の修正計画が有効で、そのパッケージについて修正版のあるすべての所見が同じ元イメージの更新待ちと判定されている
- そのパッケージのすべての写しが元イメージの層にあると確認できる
- 稼働中のイメージの実体が、修正計画の対象と一致すると確認できる

自分で追加した層にも同じパッケージがある場合や、条件を確認できない場合は表示しません。

修正計画での選び方は、[ベースイメージの特定](remediation-logic.md#base-image-selection)を参照してください。

### 更新の注意度 {#upgrade-risk}

更新の注意度は、修正版へのバージョン変更の種類を示します。

| 日本語の表示 | 意味 |
| --- | --- |
| `🟢 ディストリのセキュリティパッチ` | OSパッケージの修正版 |
| `🟢 低リスク` | 言語パッケージでメジャーバージョンが増えない変更 |
| `🟠 メジャーバージョン更新 — 要注意` | 言語パッケージでメジャーバージョンが増える変更 |
| `⚪ リスク不明` | バージョンを比較できない変更 |

緑色の表示は、更新の安全性や互換性を保証するものではありません。

### エコシステムの表示 {#ecosystem-labels}

言語パッケージの名前には、`◆ setuptools [python-pkg]`のようにエコシステムを付けます。

| 表示 | 対象 |
| --- | --- |
| `[python-pkg]`・`[npm-pkg]`・`[gobinary]`・`[jar]`など | Trivyが識別した言語パッケージの種類 |
| `[lang]` | 種類を特定できない言語パッケージ |
| タグなし | OSパッケージ |

この表示はSensorの有効・無効にかかわらず付きます。

### 参照リンク {#reference-links}

`参照:`（References）には、代表CVEに関連するリンクを表示します。

| 表示 | リンク先 |
| --- | --- |
| `アドバイザリ` | Trivyが示す主要なアドバイザリー |
| `ベンダーのアドバイザリ` | KEVの注記にあるベンダーやCISAの情報 |
| `💬 HN (N pts)` | 関連するHacker Newsの議論（Nはポイント数） |

`代表CVE:`・`ほかのCVE:`・`変化:`に表示するCVE IDは、NVDへのリンクです。
GHSAやDLAなど、CVE以外のIDは通常のテキストで表示します。

`悪用情報:`の`CISA KEV (実際の攻撃で悪用あり)`や`🧨 ランサムウェア攻撃`は、代表CVEについて得られた情報です。
優先度の判断は[悪用情報による優先度](scan-logic.md#triage)を参照してください。

## 変化の表示 {#change-labels}

差分通知では、イメージ、パッケージ、EOLの変化をそれぞれ表示します。
差分を成立させる規則は[差分と履歴の判定](diff-logic.md#comparison-baseline)を参照してください。

### イメージの変化 {#image-change-labels}

| 表示 | 読み方 |
| --- | --- |
| `🔄 イメージの内容が変化 (N件)` | 同じ参照でイメージの実体が変わった区分 |
| `イメージ更新 (旧 → 新)` | 変更前後の短縮ダイジェスト |
| `🔄 イメージ参照の更新: repo sha-A → sha-B(検出履歴を引き継ぎ)` | 参照の更新と、履歴の引き継ぎ |

参照更新の行には、リポジトリ名と変更前後のタグを表示します。
ダイジェスト固定の参照は短縮ダイジェスト、タグもダイジェストもない参照は`latest`で示します。

同じ参照に複数の実体がある場合、現在状態のイメージ見出しでは短縮ダイジェストや`linux/amd64`などを付けて区別します。

### パッケージの変化 {#package-change-labels}

| 表示 | 読み方 |
| --- | --- |
| `🆕 前回のスキャンからの新規検出 (N件)` | 新規パッケージと、変化した既知のパッケージ |
| `変化: ⬆️ 今すぐ対応に優先度昇格` | 既知のパッケージの優先度が上昇 |
| `変化: ⬆️ 要監視に優先度昇格` | 要監視への優先度上昇 |
| `変化: 新しいCVE CVE-ID` | 新たに追加されたCVE |
| `変化: 修正版が利用可能` | 修正版を利用できるようになった変化 |
| `✅ 前回のスキャンからの解消 (N件)` | パッケージの解消やEOL解除をまとめる区分 |

新規検出の見出し件数は、表示対象となるイメージ参照とパッケージの組み合わせ数です。
同じ組み合わせに複数の修正状態があれば、カードの数とは一致しない場合があります。

新規パッケージには、専用の`変化:`行がない場合があります。
通知オフからの再開表示は[通知オフの表示](#muted-display)を参照してください。

### EOLの表示 {#eol-display}

EOLのベースOSがある場合、そのイメージのEOLパッケージはベースOSの行へまとめます。
今すぐ対応のEOLパッケージは、まとめられていても今すぐ対応の区分に詳細を表示します。

| 表示 | 読み方 |
| --- | --- |
| `サポート終了(EOL)のパッケージN件を含む` | ベースOSの行にまとめたEOLパッケージ |
| `詳細: 🚨 今すぐ対応を参照` | EOLパッケージの詳細を今すぐ対応の区分に表示 |
| `新たにサポート終了(EOL)となったパッケージN件を含む` | 新規EOLのベースOSと同時に検出し、その行にまとめたパッケージ |
| `パッケージN件が新たにサポート終了(EOL)` | 既にEOLのベースOSにあるパッケージの新規EOL |
| `新規CVEのあるサポート終了(EOL)のパッケージN件` | 既にEOLのベースOSにあるパッケージのCVE追加 |
| `ベースOSのEOLが解消` | ベースOSのEOL記録がなくなった変化 |
| `サポート終了(EOL)が解消` | EOLパッケージが通常の検出結果へ移った表示 |

新規EOLのベースOSへまとめた、今すぐ対応以外の新規EOLパッケージは、EOLパッケージの差分見出し件数から除きます。
既にEOLのベースOSへまとめる変化は、件数として差分見出しに含めます。

EOL解除後も脆弱性の検出が残る場合があります。
EOLの意味は[検出結果の分類](scan-logic.md#finding-classification)、解除の判断は[解消の判定](diff-logic.md#resolved-findings)を参照してください。

## 稼働時の使用状況の表示 {#runtime-display}

Sensorの情報がある場合、パッケージに使用状況を表示します。
使用判定や観測の限界は[稼働時の使用状況](runtime-usage.md)を参照してください。

### 使用状況のラベル {#usage-labels}

| 日本語の表示 | 英語 | 読み方 |
| --- | --- | --- |
| `▶ 使用中` | in use | 使用を確認した所見 |
| `▷ 使用が確認されない` | not observed | 観測期間内に使用を確認していない所見 |
| `▷ 稼働時の使用状況を判定できない (理由)` | unavailable | 判定に必要な証拠を利用できない所見 |

チャンネルでは、使用中の所見に使用状況を付けます。
スレッドの詳細カードでは、使用が確認されない場合や判定できない場合も表示します。

簡略カードは`使用状況: ▶ 使用中 (実行中)`のように短く示します。
現在状態のレポートとスレッドでは、低優先度は個別カードを出さず、使用中の件数を区分の件数に添えます。
差分の表示では、低優先度の新規検出やCVE追加も簡略カードで表示します。

判定できない理由には、次の文言を使います。

| 対象 | 理由の表示 |
| --- | --- |
| Sensorや証拠の取得 | `Sensorの報告なし`、`Sensorの報告が古い`、`証拠が無効`、`Sensorの隔離失敗`、`権限不足` |
| 観測の準備・継続 | `索引が未構築`、`ワーカーの処理が停滞`、`証拠の切り詰め`、`証拠が不完全` |
| コンテナ | `コンテナの世代が未確認`、`コンテナが未観測` |
| パッケージ情報 | `パッケージデータベースの解析失敗`、`パッケージデータベースなし`、`パッケージデータベースのエラー`、`パッケージデータベースが未対応` |
| ファイルとの対応 | `このパッケージのファイル一覧なし`、`所有元が複数`、`ファイルが置き換えられている`、`バージョン不一致` |
| 言語パッケージとの対応 | `エコシステムの対応付けなし`、`バイナリのパス不明` |
| その他 | `不明` |

### 観測根拠の表示 {#runtime-evidence}

詳細カードでは、`使用状況:`に続けて`観測根拠:`を表示します。
利用できる情報があれば、公開状態、権限、最終確認時刻も表示します。

| 表示 | 読み方 |
| --- | --- |
| `実行中`・`読み込んだプログラム` | 実行や読み込みを確認したプログラム |
| `実行を観測`・`ライブラリ読み込みを観測` | イベントとして確認した動作 |
| `組み込み先の実行中バイナリ`・`バイナリの実行を観測` | 言語パッケージを含むバイナリの観測 |
| `稼働中の実行環境`・`実行環境の実行を観測` | 言語パッケージに対応する実行環境の観測 |
| `全インターフェースに公開` | ホストの全インターフェースへのポート公開 |
| `ループバックのみに公開` | ホストのループバックへのポート公開 |
| `待ち受け中 (未公開)` | ポートを公開せずに待ち受け |
| `高い権限で実行` | 高い権限での実行を示す情報 |
| `最終確認` | 使用を最後に確認した時刻 |

使用中の詳細表示は、代表となるコンテナの観測を示します。
複数のプログラムによる使用では、動作と`プロセス:`の一覧を分けて表示する場合があります。

```text
使用状況: ▶ 使用中
観測根拠: 実行中 /usr/sbin/nginx
公開状態: 全インターフェースに公開 · 高い権限で実行 · 最終確認06-24 09:00
```

### 通知オフの表示 {#muted-display}

通知オフの所見は個別の行を表示せず、次のように件数で示します。

```text
🔇 通知オフ — 修正版がなく7日以上使用が確認されない: 3件
```

- `優先度:`の件数と、現在の未解決の優先度件数から除外
- トリアージ無効時の現在の未解決の`CRITICAL`・`HIGH`件数から除外
- 使用状況の集計では「使用が確認されない」に含まれるため、通知オフの件数と重複
- 前回の履歴を保持していて今回の通知オフ判定を行えない項目は、保持中の未解決件数に含める

通知を再開した場合は、`変化: ↩️ 通知を再開 (使用中になった)`などと表示します。
修正版の公開や優先度昇格などの変化に該当する場合は、その変化の表示を使います。

通知オフの条件と再開理由は[修正版がない所見の通知オフ](runtime-usage.md#muting-findings-without-a-fix)を参照してください。

## 警告の読み方 {#warnings}

警告は、今回の結果を確認する際の制約を示します。
スキャン、脅威情報、Sensorでは対象が異なります。

### スキャンの警告 {#scan-warnings}

| 表示 | 読み方 |
| --- | --- |
| `⚠️ スキャン失敗` | スキャンや、ダイジェスト・プラットフォームの検証に失敗 |
| `実体未確認: 参照によるスキャン` | 発見時にDockerのconfig digestで識別できない実体を含む参照 |
| `⚠️ 実体未確認: 参照によるスキャン — 参照一覧` | 上記の参照をまとめた注記 |
| `⏳ 今回は未確認、前回の所見を保持 — 参照一覧` | スキャンには成功しても、実体を固定できない対象を含むKubernetes参照 |

実体未確認の注記は、スキャン結果とは独立した発見時の情報に基づきます。
Kubernetesの参照がすべて列挙される場合もあります。

保持の注記は、過去の履歴がない参照にも付く場合があります。
今回のスキャンがすべて失敗した参照は、この保持の一覧には含めません。

Slackの実体未確認注記と、Webhookの各イメージの実体確認結果は判定範囲が異なります。
対応するデータは[イメージの識別情報](webhook-reference.md#image-identity)、保持の扱いは[スキャン失敗時の扱い](scan-logic.md#scan-failures)を参照してください。

### 脅威情報の警告 {#intel-warnings}

| 表示 | 確認する制約 |
| --- | --- |
| `⚠️ 脅威情報 (KEV/EPSS) が利用できない — 深刻度のみで優先度を判定、低優先度への引き下げなし` | 両方の情報源を利用できない |
| `⚠️ CISA KEVデータが利用できない — 今すぐ対応の検出に漏れの可能性あり` | KEVの情報を利用できない |
| `⚠️ EPSSデータが利用できない — KEVと深刻度のみで優先度を判定` | EPSSの情報を利用できない |
| `脅威情報はN日前のもの (配信元に接続できない)` | 更新できず、以前に取得した情報を使用 |

警告の表示位置は[区分の並び順](#section-order)、判定への影響は[脅威情報を利用できない場合](scan-logic.md#degraded-triage)を参照してください。

### Sensorの警告 {#sensor-warnings}

Sensorの情報に問題がある場合、チャンネルの先頭側に次の警告を表示します。

```text
⚠️ 稼働時の証拠が利用できない: Sensorからの報告がまだない
```

理由には、次の文言を使います。

- `Sensorからの報告がまだない`
- `証拠ファイルの検証失敗`
- `Sensorの最終報告が古い`
- `Sensorの読み取りが拒否されている`
- `Sensorのサンドボックス起動失敗`
- `Sensorのサンドボックスが一部制限の効かない状態で稼働中`
- `Sensorの一部機能が利用できない`

Sensorの状態が正常でも、eBPFによるイベント観測を利用できない場合は、次のように表示します。

```text
⚠️ 短命なプログラムは観測できない (eBPFが利用できない: カーネルが未対応); サンプリングのみ使用
```

イベント観測の理由には、`カーネルが未対応`、`BTFなし`、`権限不足`、`アタッチ失敗`、`cgroup v1`、`不明`を使います。
Sensorの状態の意味と観測の限界は[稼働時の使用状況](runtime-usage.md)を参照してください。
